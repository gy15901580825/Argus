## D5 — Configure SMTP secrets in Azure Key Vault

- [ ] Login to Azure CLI (operator's workstation):
  ```bash
  az login --tenant <YOUR_TENANT_ID>
  ```
- [ ] Set SMTP secrets in `<YOUR_KEY_VAULT>`:
  ```bash
  az keyvault secret set --vault-name <YOUR_KEY_VAULT> \
      --name SMTP-HOST --value <smtp.sendgrid.net or whichever>
  az keyvault secret set --vault-name <YOUR_KEY_VAULT> \
      --name SMTP-USER --value <user>
  az keyvault secret set --vault-name <YOUR_KEY_VAULT> \
      --name SMTP-PASSWORD --value <password>
  az keyvault secret set --vault-name <YOUR_KEY_VAULT> \
      --name COST-ALERT-RECIPIENT --value <contact@example.com>
  ```
  (If SendGrid creds already exist for another service, reuse them — keep one
  set of SMTP credentials in KV.)
- [ ] In `kubernets`, edit the orchestrator chart's `ExternalSecret`
      manifest to mount these 4 keys as env vars (`SMTP_HOST`, `SMTP_USER`,
      `SMTP_PASSWORD`, `COST_ALERT_RECIPIENT`) on the orchestrator pod
- [ ] Open kubernets PR; CI green; merge
- [ ] Wait for ArgoCD prod auto-refresh (or trigger via `kubectl patch`)
- [ ] Verify env vars present in prod pod:
  ```bash
  kubectl --context <YOUR_AKS> -n default \
      exec deploy/argus-orchestrator -- env | grep -E "^(SMTP_|COST_ALERT_)"
  ```
- [ ] Force a daily-cap threshold for verification (optional):
  - Temporarily lower `daily_cap_usd` in CostMeter constructor (orchestrator side) OR
  - Trigger enough probe runs to push spent_today past 80% threshold
  - Confirm `<contact@example.com>` receives one alert email
  - Revert any temporary cap change
